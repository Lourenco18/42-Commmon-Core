- **Architecture Alignment:** Major structural decisions (4-layer separation, `Entity` base class, `GameState` enum, and `config.json` schema) were agreed upon before implementation so both teammates could work in parallel without merge conflicts.
- **Branching & Integration:** Features were developed in isolated branches and merged into `main` only after manual gameplay verification and passing `make lint`.
- **Conflict Resolution:** When overlapping edits occurred in `src/level.py` and `src/renderer.py`, both teammates reviewed the diffs together to preserve consistent naming, type annotations, and PEP 257 docstrings.

## 3. Summary of Blocking Points and Resolutions

1. **Maze Bitmask Polarity (`A-Maze-ing` Integration):**
   - *Issue:* Initial maze rendering inverted walls and corridors because we assumed set bits represented open passages rather than walls.
   - *Resolution:* Inspected the raw `mg.maze` matrix generated by `mazegenerator-2.1.0-py3-none-any.whl`, confirmed that bits `1 (N), 2 (E), 4 (S), 8 (W)` indicate walls, and aligned `Maze.is_wall()` accordingly.

2. **Central `"42"` Closed Cells Trapping Player Spawn:**
   - *Issue:* On certain maze dimensions, the center coordinate `(height // 2, width // 2)` landed inside a fully walled cell (`bitmask = 15`) belonging to the generator's `"42"` signature pattern, immobilizing Pac-Man and resulting in zero placed pacgums.
   - *Resolution:* Implemented `Level._find_spawn_cell()` using BFS to locate the nearest reachable corridor cell to the center, and constrained pacgum placement to `_reachable_cells()`.

3. **`Level.__init__` Attribute Initialization Order Bug:**
   - *Issue:* During refactoring, `_find_spawn_cell()` was initially invoked before `self.maze = generate_maze(...)`, raising `AttributeError: 'Level' object has no attribute 'maze'`.
   - *Resolution:* Reordered `Level.__init__` so `self.maze` is instantiated and validated before computing the player's spawn coordinates.

4. **Shared Wall-Collision Refactoring (`Entity` Base Class):**
   - *Issue:* `Player` and `Ghost` initially checked wall collisions through separate code paths.
   - *Resolution:* Extracted `Entity` (`can_move()`, `available_moves()`, `visual_pos()`) and `Collectible` in `src/entities.py` so both actors inherit identical wall-collision behavior.

5. **PyInstaller Asset Resolution (`_MEIPASS`):**
   - *Issue:* Running the standalone `dist/pacman` executable initially fell back to geometric circles because relative `"assets/..."` paths did not point to PyInstaller's temporary extraction folder.
   - *Resolution:* Configured `datas` in `pacman.spec` and updated `ASSET_DIR` in `src/renderer.py` to resolve via `getattr(sys, "_MEIPASS", ...)`.
